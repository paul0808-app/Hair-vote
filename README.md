# ヘアスタイル投票アプリ（Hair-vote）

美容室（PAUL西葛西店・COコ西葛西南口店）の各席のタブレットで、
お客様が好きなヘアスタイル写真に「いいね」して投票するアプリです。

## いまできること

### 投票画面（トップ）
- ヘアスタイル写真を格子状（グリッド）に表示
  - iPad 横向き（1024px〜）＝ **5列** / iPad 縦向き（640〜1023px）＝ **4列** / スマホ＝ **3列**
- 写真をタップすると**拡大モーダル**が開く
- 選択された写真は、**太いピンクの枠線・右上の番号バッジ・薄い暗色・チェックマーク**の4つが同時に付く
- 画面下の固定バーに `2枚 / 5枚 選択中` とドット（●●○○○）。0枚のときは「投票へ進む」が押せない
- 5枚そろうとバーの色が変わって「選択完了！」になる

### 写真の拡大モーダル
- 拡大した写真＋スタイル名・担当スタイリスト・説明文・ハッシュタグ
- 大きな**「いいね」ボタン**（選択済みなら「選択を解除」に変わる）
- **左右スワイプ**、または左右の矢印ボタンで前後の写真へ移動
- **×ボタン・背景タップ・下スワイプ**のいずれでも閉じられる
- 5枚選んだ状態で6枚目を押すと「最大5枚までです」というお知らせが2秒だけ出る

### 投票確認ダイアログ
- 「本当に投票しますか？」＋選んだ写真のサムネイル
- 5枚のときは「選んだ5枚で投票を確定します。確定後は変更できません。」
- 5枚未満でも投票でき、その場合は「3枚で投票します。よろしいですか？」のように枚数が入る

### 投票完了画面
- 「ご投票ありがとうございました」＋選んだ写真
- 画面下に「次のお客様へ」ボタン。**1タップ**でリセットし、次のお客様の投票を受け付ける

### 投票セッションの決まりごと
- 初回アクセス時に `crypto.randomUUID()` でセッションIDを作り、ブラウザに保存
- URLに `?seat=A1` のように席番号を付けると、そのセッションに記録される
- 選択途中の状態はブラウザに保存され、閉じても開き直せば復元される
- 投票を確定するとその回は**読み取り専用**になり、変更や追加投票はできない
- 確定から**30分**たつ、または「次のお客様へ」を押すと、自動的に次の投票を受け付ける

### データベース（Supabase）への保存
- 写真の一覧を `styles` テーブルから取得（5分間キャッシュしてDBへの負荷を抑える）
- 「投票を確定する」を押した**その1回だけ**データベースに書き込む
- 保存はデータベース側の関数 `submit_ballot` が**1つのトランザクション**として実行するので、
  途中で失敗しても中途半端なデータが残らない
- 枚数の上限（5枚）・重複・存在しない写真のチェックを**サーバー側でも**行う
- URLに `?salon=PAUL` / `?salon=COCO` を付けると、その店舗として記録される

**まだできないこと（フェーズ4以降）**
集計を見るための管理画面（ランキング・CSV・写真の登録）。

**写真について**
いまはサンプル画像（picsum.photos）を登録しています。
実際のヘアスタイル写真はフェーズ4の管理画面から登録できるようにします。
通信の都合で写真が届かないときは、スタイル名だけのグレーのタイルになります。

**接続していないときの動作**
環境変数が未設定、またはデータベースにつながらないときは、
画面が真っ白になったりせず**仮データで表示**され、写真の枚数の横に「（仮データ）」と出ます。
その状態では投票は保存されません（保存に失敗した場合は完了画面に進まず、お知らせが出ます）。

## Supabase の設定手順（iPadだけで完了します・所要15分ほど）

**用語**：Supabase＝データを保存しておく置き場（データベース）のサービスです。

### 1. プロジェクトを作る

1. Safari で **https://supabase.com** を開き、ログイン
2. **Dashboard**（最初に出る画面）で **「New project」** を押す
3. 入力するもの
   - **Name**：`hair-vote`（何でもOK）
   - **Database Password**：自動生成のままでOK。**このパスワードは今回使いません**
   - **Region**：**Northeast Asia (Tokyo)** を選ぶ（日本から一番速い）
4. **「Create new project」** を押して、1〜2分待つ

### 2. テーブルを作る

1. 左側のメニューから **「SQL Editor」**（紙とペンのようなアイコン）を開く
2. **「New query」** を押す
3. このリポジトリの **`supabase/schema.sql`** の中身を**すべて**コピーして貼り付ける
   - GitHubアプリやSafariで `supabase/schema.sql` を開き、全選択してコピー
4. 右下の **「Run」** を押す。`Success. No rows returned` と出れば成功
5. 同じ手順で **`supabase/seed.sql`**（サンプル写真30件）も貼り付けて **Run**
6. 左メニューの **「Table Editor」** を開き、`styles` に30行入っていれば完了

### 3. 接続情報を2つコピーする

左下の **「Project Settings」**（歯車アイコン）→ **「API」** を開きます。
（新しい画面では **「API Keys」** という項目名になっている場合があります）

コピーするのは次の2つです。

| 何をコピーするか | どこにあるか | Vercelでの名前 |
|---|---|---|
| プロジェクトのURL | **Project URL** の欄（`https://〇〇.supabase.co`） | `SUPABASE_URL` |
| 秘密の鍵 | **Project API keys** の **`service_role`** の行の「Reveal」を押して表示される長い文字列 | `SUPABASE_SERVICE_ROLE_KEY` |

> 新しいSupabaseの画面では、`service_role` は **「Legacy API keys」** タブの中にあります。
> または **「Secret keys」** にある `sb_secret_...` で始まる鍵でも構いません。
>
> ⚠️ **`service_role` の鍵は絶対に人に見せないでください。** これ1つでデータベースを
> 全部操作できます。`anon` / `publishable` のほうの鍵ではないので注意してください。

### 4. Vercel に貼り付ける

1. **https://vercel.com** → プロジェクト **Hair-vote** を開く
2. 上部の **「Settings」** タブ → 左メニューの **「Environment Variables」**
3. 次の2つを追加する（**Key** に名前、**Value** に貼り付け、**Add** を押す）

   | Key | Value |
   |---|---|
   | `SUPABASE_URL` | 手順3でコピーした Project URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | 手順3でコピーした service_role の鍵 |

   環境（Production / Preview / Development）は**すべてにチェック**を入れてください。
4. 上部の **「Deployments」** タブ → いちばん上のデプロイの右の **「…」** → **「Redeploy」**
   - 環境変数は**貼っただけでは反映されません。必ず Redeploy が必要**です

### 5. つながったか確認する

投票URLを開いて、写真の枚数の横に **「（仮データ）」が出ていなければ接続成功**です。
出ている場合は、環境変数の名前のスペルと、Redeploy をしたかを確認してください。

## iPad だけでの公開手順（初回だけ・所要10分ほど）

PCは不要です。iPad の Safari だけで完了します。

### 1. Vercel にログインする

1. Safari で **https://vercel.com** を開く
2. 右上の **「Sign Up」**（または Log In）→ **「Continue with GitHub」** を選ぶ
3. GitHub のアカウントでログインし、Vercel からのアクセスを許可する

### 2. このリポジトリを取り込む

1. ログイン後の **Dashboard**（最初に出る一覧画面）で **「Add New...」→「Project」** を押す
2. **「Import Git Repository」** の一覧から **`Hair-vote`** を探して **「Import」** を押す
   - 一覧に出ないときは、その下の **「Adjust GitHub App Permissions」** から `Hair-vote` を許可する
3. **Framework Preset** が **Next.js** になっていることを確認（自動で入ります）
4. 設定は何も変えずに **「Deploy」** を押す

### 3. できあがったURLを開く

- 1〜2分待つと「Congratulations」の画面になります
- 表示された **`https://hair-vote-〇〇〇.vercel.app`** のURLが投票画面です
- このURLをタブレットの Safari で開いてください

### 4. 開発中のブランチを見るには

いまの作業は `main` ではなく **`claude/hairstyle-voting-app-5w5suj`** というブランチにあります。

- Vercel の Dashboard → プロジェクト名 → 上部の **「Deployments」** タブを開く
- ブランチ名が `claude/hairstyle-voting-app-5w5suj` の行をタップ
- **「Visit」** ボタンでプレビューURLが開きます（このURLで今の画面を確認できます）

> 以降は、このリポジトリに変更を push するたびに Vercel が自動でURLを更新します。
> 何も操作は要りません。

## 技術メモ（開発者向け）

- Next.js 16（App Router）+ TypeScript + Tailwind CSS v4
- 選択状態は React の state と `localStorage` のみで管理し、**データベースには書き込まない**
  （投票確定時に1回だけ書き込む設計。フェーズ3で実装）

### 同時接続について

タブレット1台＝1ブラウザ＝独立した `localStorage` なので、何台から同時に開いても
互いの選択状態に影響しない。5台同時に投票・確定・リセットする自動テストで、
セッションIDと選択内容がそれぞれ独立していることを確認済み。

フェーズ3でデータベースに接続したあとも、書き込みは「お客様1人あたり確定時の1回だけ」に
限定する。あわせて `UNIQUE (ballot_id, style_id)` 制約と、カウンターを持たず `COUNT` で
集計する方針により、同時書き込みで票数がずれないようにする。
